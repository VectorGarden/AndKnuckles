# Asset pipeline

Everything the S&K title screen draws is decoded from the disassembly's own data
rather than screenshotted, then pasted into `index.html` as base64 PNGs. This is
that pipeline. Nothing here ships in the page — it exists so the artwork can be
rebuilt, checked, or changed.

```bash
node tools/build-all.mjs            # everything, in order
node tools/build-all.mjs --check    # verify without changing anything
```

`--check` restores whatever it found and exits non-zero if the pipeline and the
committed `index.html` disagree, so it is safe to run against a dirty tree. It runs
on every pull request via [`.github/workflows/assets.yml`](../.github/workflows/assets.yml),
so the page and `tools/` cannot drift apart without the check failing.

The steps underneath, if you want to run one on its own:

```bash
node tools/build-sk-assets.mjs      # rom/ -> out/  (17 PNGs + intro-meta.json)
node tools/build-s3-assets.mjs      # rom/ -> out/  (background + banner sheet)
node tools/build-font.mjs           # font/ -> out/ (sprite font atlas + glyph table)
node tools/embed-assets.mjs         # out/  -> index.html
```

Reach for `build-all` by default. `embed` only touches scenes whose files are in
`out/`, which is the sane behaviour for a partial run but means running two of the
three builds and then embedding would quietly ship a page assembled from a stale
`out/`. `build-all` wipes `out/` first and runs the lot.

## What build-sk does

1. **Kosinski** and **moduled Kosinski** for the tile art — background, the
   standing Sonic/Knuckles blob, the landing frames, the Death Egg, the mountain,
   falling Sonic, and the hand animation art.
2. **Replays the runtime DMAs.** The tiles for Knuckles' face and fists are
   placeholders in the ROM blob; `Obj_SKTitle_HandAnim` overwrites them at
   runtime. Skip that and you get leftover garbage across his chest.
3. **Enigma** for the plane tilemaps — the background and the four
   `SK SonicKnux Frame` poses.
4. **Composes** the layers, crops each to what it actually covers, and writes
   indexed PNGs plus `intro-meta.json` (offsets, anchors, and the hand channels'
   frame tables).

The hand overlays are generated by patching the standing art one channel-state at
a time, re-rendering Plane A, and keeping only the pixels that changed — which is
why all eight together come to about 3 KB.

## What build-s3 does

The S3 screen is two planes rather than a layer stack: **Enigma** for both, plane B
the sky and scenery, plane A Sonic and the foreground drawn over it with index 0
transparent, over **Kosinski** tile art. The banner is a sprite in the original and
part of neither plane — which is exactly the gap the generated text drops into.

It also writes `s3-banner-tiles.png`, which is **not embedded**. That is
`ArtNem_Title_S3Banner` — Nemesis, 214 tiles — dumped as a grid so the real **3**
can be read off it. The digits were drawn against that, which is where their flat
terminals and 45° chamfers come from.

Neither background carries a `tRNS` chunk. They are opaque by definition and will
happily use their lowest palette slot as a real colour; reserving index 0 for
transparency punches holes in them. It did exactly that to Sonic's pupils once.

## What build-font does

The one build here that is **not** a decode. The ROM has no title font at all:
`Map - S3 ANDKnuckles.asm` is six sprite pieces making a flat 168&times;24 bitmap of
the phrase, so only **& C E K L N S U** trace to real game pixels. The other twenty
letters were reconstructed by the ripper, and the digits and punctuation were drawn
for this project.

So `font/base/` is **source data, not something regenerable** — the ripped sheet,
28 glyphs, credited in the root README. The build is additive on top of it:

| stage | source | glyphs |
|---|---|---|
| ripped sheet | `font/base/` | 28 |
| + digits | `font/masks.mjs` | 38 |
| + keyboard punctuation | `font/punct.mjs` | 68 |

Both generated sets are authored as `#` masks at plain size and run through the
same shading rule in `lib/shade.mjs`, so they cannot drift from the sheet's own
weight — gold body, ember on the right of every horizontal run and the bottom of
every vertical one, flare a pixel in from the left, and an L-shaped glint at the
top-left corner. Fed the real **I**'s outline that rule reproduces the real **I**
pixel for pixel, which is what made it safe to point at shapes the game never drew.

`'0'` is not drawn at all: it is the real **O**'s own mask, so the two cannot
disagree. `'9'` is `'6'` rotated 180&deg; in `masks.mjs` for the same reason.

The build asserts what the layout depends on: every glyph's height matches its
style's row height, and no glyph overflows its row band once its `yOffset` is
applied. Both are how a period ends up on the baseline and a quote at cap height
without padding the bitmap.

## What embed preserves

Only the artwork and the geometry that comes with it are replaced. Every timing
value — the camera phases, the shake, the reveal, and the hand channels' `phase`
and `delay` — is read back out of `index.html` and kept. Regenerating the art
cannot silently undo tuning that was arrived at by eye.

## rom/

Compressed source data from the [Sonic Retro disassembly][disasm], unmodified.
It is Sega's, like the rest of the artwork this project renders — see the credits
in the root README. The page already embeds the decoded results; these are the
inputs they came from, kept here so the build runs without a network fetch.

`lib/` is the decoder set: Kosinski and moduled Kosinski, Enigma, Nemesis (for the
S3 logo), and an indexed-PNG reader/writer. They were written against
[flamewing/mdcomp][mdcomp]; the traps worth knowing about are recorded in the root
README under *Compression formats implemented*.

[disasm]: https://github.com/sonicretro/skdisasm
[mdcomp]: https://github.com/flamewing/mdcomp
